# 关联项目候选发现

执行 `project-inbox refresh`，或调用 MCP 的 `refresh_projects`，会发现并合并候选到 `config/projects.yaml`，再将项目名称同步到看板的 `backlog/config.yml`。刷新不修改任务的已有归属。

当前 Backlog 配置监听器会拒绝现有 YAML 块列表格式，运行中的看板可能继续使用旧选项。确认没有正在保存的编辑后，用 `launchctl kickstart -k gui/501/com.projectinbox.board` 重新加载本机服务，再刷新页面。本轮未修改上游监听器或列表序列化规则。

## 筛选范围与时间

- 只扫描 `config/settings.yaml` 中的三个 `scan_roots`，沿用 `max_depth`，最大支持八层。不跟随符号链接，不进入隐藏、敏感、依赖与常见生成目录。
- 三个月按配置的 `timezone` 从刷新时刻向前推三个自然月，包含起点；目标月份没有对应日期时取月末。不是固定九十天，也不是 Agent 会话使用时间。
- 纳入全部符合条件的项目，取消原先每次前十个的限制。较早的已登记项目继续保留，人工名称、别名、关键词、简介与启用状态不覆盖。

## 修改记录

Git 项目读取本地各分支和标签可达提交的提交者时间，并检查暂存、未暂存、未跟踪文件的修改时间。Git 忽略文件、依赖、缓存、构建输出等不作为本地改动证据。删除文件已经没有修改时间，使用最近仍存在的父目录修改时间近似判断；文件时间可能受复制、恢复或系统时钟影响，不等同完整开发历史。仅打开 Agent 会话不会使项目入选。

没有 Git 的目录需要存在项目标识，例如 `package.json`、`pyproject.toml`、`requirements.txt`、`Cargo.toml`、`go.mod`、`Package.swift`、`Makefile` 或 Xcode / C# 项目文件。按非隐藏本地文件的修改时间筛选，跳过常见生成与敏感目录。标识位于子目录时，归到扫描根目录下对应的顶层项目，避免把同一项目的多个组件分别登记。

新登记项目的显示名称取目录名。看板要求显示名称唯一，所以不同位置的同名目录（例如两个 `web`）中，后登记的会加上上级目录名（`groupb-web`），仍重名时再加短哈希；已登记项目的名称不会被改动，可在 `config/projects.yaml` 里自行调整。项目 ID 以字母或数字开头，目录名开头的下划线和横线会被去掉。

共享 Git common dir 或相同脱敏远程标识的仓库沿用现有合并规则，作为同一项目的工作目录。嵌套独立 Git 仓库可单独入选；无项目标识的普通资料目录不自动登记。

扫描只读取 Git 元数据、路径、文件时间和已入选项目的白名单简介，不执行项目代码，不读取会话正文，不联网。刷新结果的 `discovery` 包含时间起点、候选数量、入选路径和最近修改时间；注册表沿用 `last_active` 字段承载本轮修改时间，`activity_sources` / `time_bases` 标明证据来源。
