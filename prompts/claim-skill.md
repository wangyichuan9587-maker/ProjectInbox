从 ProjectInbox 认领任务，并按交接单做完。下面的 `pi` 指这条命令：

```
{{CLI}}
```

1. **选卡**
   - 用户给了编号：直接认领那张。
   - 没给编号（「认领下一张」）：运行 `pi list --status todo`，只在**带「交接单」标签**的卡里选；有多张时列给用户选，不要替用户挑。
   - 没有可认领的卡：说明只有交接单进了待办的卡才能领，列出还卡在收件箱的卡和它们的待确认问题，然后停下。
2. **认领**：先看当前会话目录（`pwd`）。
   - 会话本身已经在这个项目的独立 worktree 里（例如 Claude Code 桌面版的 `.claude/worktrees/…`）：运行 `pi claim --agent claude-code --here "$(pwd)" <TASK-n>`。程序直接在会话目录里开任务分支，不再另建工作区，编辑不会被会话的 worktree 保护拦下。
   - 否则：运行 `pi claim --agent claude-code <TASK-n>`，程序在项目的 `.worktrees/task-n` 建工作区。
   - 用户说出认领就是授权，不用再问。认领失败（被别人领走、状态不对、会话目录有没提交的改动）就原样告诉用户并停下。领取包里有 `note` 时照它说的做。
3. **开工前**：读领取包里的交接单。严格按「这次要做 / 这次不做」和验收清单干，范围外的事一律不做；交接单与代码现状对不上时，先告诉用户，不要自己扩大范围。只在领取包返回的 `workspace` 里改代码并提交。
4. **做完**：按交接单里的验证命令实际验证，再运行 `pi report-template <TASK-n>` 拿汇报单空表，如实填写（改了什么、怎么看到效果、验证结果、没验证到的也要写明），运行 `pi submit-report --file <文件> --agent claude-code` 提交。汇报单被程序退回就按提示补齐再交，不要绕过检查，也不要直接改看板文件。
5. **做不了**：运行 `pi release --agent claude-code --reason <原因> <TASK-n>` 放回待办，并告诉用户原因。
6. **记一笔**：要往卡片备注里补话，用 `pi note <TASK-n> --text "<内容>"`，它只会往后追加；不要用 `update` 改 notes。
7. **收尾**：汇报提交后，只告诉用户卡片现在是 review 状态、在哪里看效果。**不要**合并、推送、部署，也不要运行 `done`、`accept`、`reject`、`cancel`；用户说「验收通过」时才运行 `pi done <TASK-n>`（它会一并快进合并进主分支、删工作区，被拒就把原话转告用户）。
